# fp32 行走为什么慢:占用率调查(2026-10-22,pod 32741,C600-U 28 AP,MACA 20261017)

状态:**已落地**(`kThreads` 640 → 512,见 §3)。问题:coarse12 两遍行走在核 ~780-880 GB/s(官方 5.618 ms
旗舰格 × 相位份额 43.3%/49% 折算),同形状复刻微基准 1226-1310 GB/s ——
~40% 的差距归因为何。

## 1. doctor + 驱动回答的占用(已测)

`maca_kernel_doctor`(--timeout 300,编译 TU)读数
`topk_coarse12_kernel<640>`:**51 MT / 76 ST / 1308 B 静态 smem,0 栈帧**。

驱动回答(`cudaOccupancyMaxActiveBlocksPerMultiprocessor`,本仓纪律:占用
只问驱动,不手算):

| 动态 smem | CTA/SM |
| ---: | ---: |
| 16 KB(生产) | **3** |
| 0(对照) | **3** |

**上限是 2048 线程/AP 的天花板,不是 smem,也不是寄存器**:640×3 = 1920,
4 个 CTA 需要 2560 > 2048;寄存器 51 MT × 640 × 4 = 130,560 ≤ 131,072 本来够
4 个。smem(1308 + 16384)× 7 ≈ 124 KB 也够 7 个 —— 线程数是唯一瓶颈。
**512 线程 = 4 CTA = 2048 线程满填**,且在飞字节 30 → 32 KB(+7%),复基准
同形状 512 vs 640:纯读 +10.6%、逐元素原子 +6.4%、过滤+暂存 +6.5%。

在核 walk 已带 OUT=2(`topk_coarse12.cuh` 的 `ARCH_REGS_PER_AP >= 131072`
门,xcore1600 满足),所以差距不在在飞 float4 数。

GB/s 是算子自身的逻辑流量(`B·V·4` 或 `B·V·2`,单次读),与 `perf_data` 的
`bandwidth(GB/s)` 同义,不是核内纯读墙。三轮都同向,且两个对照(bf16)
比值 0.998 —— 512 的收益全部落在 coarse12 服务的 fp32 格上,bf16 路由不经过
这个核,所以不动。

**判定:瓶颈是 2048 线程/AP 天花板,不是 smem、不是寄存器。** kThreads=640
时 3 CTA/SM = 1920 线程,离 2048 差 128;4 个 CTA 需要 2560。smem
(1308 + 16384 = 17692 B)能放 7 个,寄存器(51 MT)按 4 个 CTA 算
51×640×4 = 130,560 ≤ 131,072 也够 —— 驱动读数(§1)两个对照都停在 3。
512 线程 = 4 CTA = 2048 整,在飞字节 30 → 32 KB(+7%),复基准同形状
纯读 +10.6%、逐元素原子 +6.4%、过滤+暂存 +6.5%;在算子里是 3.7-6.2%
(五个 fp32 格),差值被算子的其余相位稀释。

**仍未到墙,这次只关掉了占用这一项。** 两遍行走本身在同形状复基准是
1226-1310 GB/s,核内按相位份额折算是 780-880 GB/s;512 之后核内约 820-925,
与墙(本 pod 1650 GB/s 量级,见 C600U 记忆)和复基准都还有距离。剩余差距在
相位结构 —— pass1 43.3% / narrow 2.4% / collect 48.6% / arena 5.6%
(640 构建的份额),两遍之间的串行段和空洞 —— 下一杠杆应从那里找,不是继续
加 CTA(4 已是天花板)。

门禁:512 构建(`/tmp/t512`,md5 `5958dcea`)上
`tests/test.py --backend maca_c --sample 342 -rf`,491 例 = 342 抽样正确性 +
147 官方网格 + 2 selector:**pass 486 / check_fail 0 / crash 0 /
unsupported 0 / skip 5**,5 个 skip 全是 `b4096` × `V≈0.4-1.0M` 的
`torch.cuda.OutOfMemoryError`(进程本身占着 ~45 GB,单卡 72 GB),是环境,
不是答案。

落地:`csrc/maca_kernels/common/topk_coarse12.cuh` 的 `kThreads` 640 → 512
(唯一拼写处,声明/显式实例化/`__launch_bounds__`/launch 同步),注释随之
更新;`csrc/maca_kernels/common/routing.cuh` 里"640 threads against 512"的

测量只在 C600U(device 1)上做,C500/C600 未测。
