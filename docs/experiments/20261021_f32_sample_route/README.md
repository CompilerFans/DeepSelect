状态:**微基准已写好,尚未在设备上跑**。这是 `20261021_reference_recon` §7 的
关键未知量:采样路线的一遍"过滤+暂存"行走到底跑多快,决定成本模型取
1.77× 还是 2.93× 那一端。算法可行性(欠收/溢出概率)已在官方分布上由
`20261021_reference_recon/sim_sample_np.py` 解决,不在本文重复。

归属:采样-过滤-选择 = LiteTopK(arXiv 2607.11976);DeepSelect issue #13
要求归属。vLLM PR #48726 / SGLang PR #32094 同路线。

## 1. 路线设计(落地形态的草案)

1. **采样**:读行的连续前缀(V/16),建 4096 桶(12 位)直方图,取第 m 大
   有序 key T,裕量 m = ceil(1.4k·s/V)(k<1024 用 1.6k —— 模拟里 k512 在
   V/16 1.4k 下有 1.56–6.25% 欠收)。
2. **一趟过滤+暂存**:整行行走,{key > T} 进 arena:idx32[4096] +
   key32[4096](32 KB;幸存者期望 ≈1.4k,约占行的 1.1%)。
3. **smem 内精化**:候选自带 32 位 key,精化是 coarse12 arena 三轮的纯
   smem 版 —— **不需要按索引回 gather 全局**(这正是 bf16 一趟式 compact
   的实测死因,`C600U-algorithm-choice.zh.md` §2.3)。
4. **回退**:欠收(count<k)或溢出(count>4096)→ 现有 coarse12 两遍。
   官方分布模拟两者 P≈0(256 行,`sim_sample_np.py`)。
5. 收尾走不变的契约半(preselected)。

smem 预算:32 KB arena + ~1 KB 静态 vs C600U 128 KB/AP;占用由驱动回答
(640 线程 × 3 CTA = 99 KB,理论可行 —— **以驱动为准,不手算**)。

## 2. 微基准回答什么

| 臂 | 回答 |
| --- | --- |
| 0 纯读 | 该几何(线程数 × 一 CTA 一行)的天花板 |
| 1 逐元素原子直方图 | = coarse12 pass-1 的复刻,校准已知 ~772 GB/s 档 |
| 2 过滤+暂存 idx(16 KB) | 采样路线的一遍行走(无 sidecar 变体) |
| 3 过滤+暂存 idx+key(32 KB) | 采样路线的真实形态 |
| 4 仅过滤(无线程外写) | 拆分 行走+比较 与 ~1.1% 幸存者的暂存成本 |
| 5 臂 2 的 OUT=2 | MLP 假设:两个 float4 在飞是否提速 |

三个宽度(512/640/1024 线程)顺带预演线程宽度扫描的行走侧效果,**不需要**
全树构建(对比:真内核改宽度 = 一次 90-TU 构建)。

判读:

- **臂 2 ≈ 臂 0 × ≥0.85** → 路线收益取区间上端(≈2.6–2.9×),直接排进
  下一个 pod 会话的内核补丁。
- **臂 2 ≈ 臂 1** → 过滤行走与直方图行走同速(都 ~772),收益 = 删掉
  pass-2 的整行读 ≈ 2×,仍值得做,但先看相位探针的 pass-1/pass-2 拆分
  是否另有解释。
- **臂 5 ≫ 臂 2** → MLP 受限坐实,先修 MLP(OUT=2 / 宽度),路线收益
  复合其上。
- **臂 4 ≈ 臂 2** → 暂存免费,32 KB sidecar 变体(臂 3)的占用代价是
  唯一需要权衡的;若臂 4 ≫ 臂 2,幸存者的原子/写在拖,考虑减小裕量。

## 3. 跑法(pod 上)

```bash
# cucc 在 $MACA_PATH/tools/cu-bridge/bin/ 下(PATH 里没有就写全路径)
cucc -O3 --offload-arch=xcore1600 -shared -fPIC \
     docs/experiments/20261021_f32_sample_route/filter_stage.cu -o /tmp/fs.so
DS_TESTS=/root/github/DeepSelect/tests \
     python docs/experiments/20261021_f32_sample_route/filter_stage_run.py /tmp/fs.so
```

编译秒级(自包含单文件,无仓内 include);运行约 1 分钟(3 形状 × 18 臂)。
阈值由驱动用 `torch.topk` 预计算(每行 rank-ceil(1.4k) 的真值 key,
k512 用 1.6k),与模拟的裕量规则一致;out_count 读回校验候选数
(min/med/max 对 m 和 4096 容量)。

**与相位探针的顺序**:先跑 `20261021_coarse12_phase`(它归因现行两遍的
47%-of-墙),再跑本基准(它给替代路线的速率)。两者合起来决定 §1 路线
补丁的预期收益,再决定是否花一次全树构建。
