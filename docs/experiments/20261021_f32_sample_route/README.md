# fp32 采样阈值一趟:过滤+暂存微基准与路线设计(2026-10-21,准备中)

状态:**微基准已写好,尚未在设备上跑**。这是 `20261021_reference_recon` §7 的
关键未知量:采样路线的一遍"过滤+暂存"行走到底跑多快,决定成本模型取
1.77× 还是 2.93× 那一端。算法可行性(欠收/溢出概率)已在官方分布上由
`20261021_reference_recon/sim_sample_np.py` 解决,不在本文重复。

归属:采样-过滤-选择 = LiteTopK(arXiv 2607.11976);DeepSelect issue #13
要求归属。vLLM PR #48726 / SGLang PR #32094 同路线。

## 1. 路线设计(落地形态的草案)

1. **采样**:读行的连续前缀(V/16),建 4096 桶(12 位)直方图,取第 m 大
   有序 key T,裕量 m = ceil(1.4k·s/V)(k<1024 用 1.6k —— 模拟里 k512 在
   V/16 1.4k 下有 1.56–6.25% 欠收)。
2. **一趟过滤+暂存**:整行行走,{key > T} 进 arena:idx32[4096] +
   key32[4096](32 KB;幸存者期望 ≈1.4k,约占行的 1.1%)。
3. **smem 内精化**:候选自带 32 位 key,精化是 coarse12 arena 三轮的纯
   smem 版 —— **不需要按索引回 gather 全局**(这正是 bf16 一趟式 compact
   的实测死因,`C600U-algorithm-choice.zh.md` §2.3)。
4. **回退**:欠收(count<k)或溢出(count>4096)→ 现有 coarse12 两遍。
   官方分布模拟两者 P≈0(256 行,`sim_sample_np.py`)。
5. 收尾走不变的契约半(preselected)。

smem 预算:32 KB arena + ~1 KB 静态 vs C600U 128 KB/AP;占用由驱动回答
(640 线程 × 3 CTA = 99 KB,理论可行 —— **以驱动为准,不手算**)。

## 2. 微基准回答什么

| 臂 | 回答 |
| --- | --- |
| 0 纯读 | 该几何(线程数 × 一 CTA 一行)的天花板 |
| 1 逐元素原子直方图 | = coarse12 pass-1 的复刻,校准已知 ~772 GB/s 档 |
| 2 过滤+暂存 idx(16 KB) | 采样路线的一遍行走(无 sidecar 变体) |
| 3 过滤+暂存 idx+key(32 KB) | 采样路线的真实形态 |
| 4 仅过滤(无线程外写) | 拆分 行走+比较 与 ~1.1% 幸存者的暂存成本 |
| 5 臂 2 的 OUT=2 | MLP 假设:两个 float4 在飞是否提速 |

三个宽度(512/640/1024 线程)顺带预演线程宽度扫描的行走侧效果,**不需要**
全树构建(对比:真内核改宽度 = 一次 90-TU 构建)。

判读:

- **臂 2 ≈ 臂 0 × ≥0.85** → 路线收益取区间上端(≈2.6–2.9×),直接排进
  下一个 pod 会话的内核补丁。
- **臂 2 ≈ 臂 1** → 过滤行走与直方图行走同速(都 ~772),收益 = 删掉
  pass-2 的整行读 ≈ 2×,仍值得做,但先看相位探针的 pass-1/pass-2 拆分
  是否另有解释。
- **臂 5 ≫ 臂 2** → MLP 受限坐实,先修 MLP(OUT=2 / 宽度),路线收益
  复合其上。
- **臂 4 ≈ 臂 2** → 暂存免费,32 KB sidecar 变体(臂 3)的占用代价是
  唯一需要权衡的;若臂 4 ≫ 臂 2,幸存者的原子/写在拖,考虑减小裕量。

## 3. 跑法(pod 上)

```bash
# cucc 在 $MACA_PATH/tools/cu-bridge/bin/ 下(PATH 里没有就写全路径)
cucc -O3 --offload-arch=xcore1600 -shared -fPIC \
     docs/experiments/20261021_f32_sample_route/filter_stage.cu -o /tmp/fs.so
DS_TESTS=/root/github/DeepSelect/tests \
     python docs/experiments/20261021_f32_sample_route/filter_stage_run.py /tmp/fs.so
```

编译秒级(自包含单文件,无仓内 include);运行约 1 分钟(3 形状 × 18 臂)。
阈值由驱动用 `torch.topk` 预计算(每行 rank-ceil(1.4k) 的真值 key,
k512 用 1.6k),与模拟的裕量规则一致;out_count 读回校验候选数
(min/med/max 对 m 和 4096 容量)。

**与相位探针的顺序**:先跑 `20261021_coarse12_phase`(它归因现行两遍的
47%-of-墙),再跑本基准(它给替代路线的速率)。两者合起来决定 §1 路线
补丁的预期收益,再决定是否花一次全树构建。

## 4. 结果(2026-10-21,pod 30752,C600-U 28 AP,MACA 20261017,设备 1)

**微基准**(形状 b4096 V131072 k2048,640/512/1024 线程,候选阈值 m=2868):

| 臂 | 640 | 512 | 1024 |
| --- | ---: | ---: | ---: |
| 纯读(天花板) | 1356 | **1500** | 1454 |
| 逐元素原子(coarse12 p1 复刻) | 1226 | 1305 | 1237 |
| 过滤+暂存 idx 16 KB | 845 | 900 | 852 |
| 过滤+暂存 idx+key 32 KB | 825 | 709 | 847 |
| 仅过滤 | 1252 | 1322 | 1245 |
| 过滤+暂存 OUT=2 | 967 | 1038 | 967 |

读法:fp32 逐元素原子**不构成约束**(1226-1310 ≈ 88% 墙);过滤免费;
**单计数器暂存是唯一大头**(845 vs 1252,幸存率 2.2%);OUT=2 +14%;
512 线程是最佳宽度。候选数驱动校验 min 2866 med 2867 = 模拟 E=2863 ✓。

**coarse12 相位探针**(`20261021_coarse12_phase`,同 pod):旗舰格
pass1 **43%** / fold+narrow 2.4% / collect **49%** / arena 5.6% ——
两遍行走同速(~600-670 GB/s 在核),瓶颈是行走本身(占用/MLP),
不是原子。复基准的 1226-1310 是在核行走的 ~2 倍 —— 占用率差是真内核
与复刻内核的区别(寄存器/常驻 CTA 数)。

**原型**(`proto_sample.cu` + `proto_run.py`,采样 V/16 → 12-bit 直方图 →
阈值 bin 地板 → 一遍过滤+暂存 → 4 轮 8-bit smem 精化 → 欠收/溢出/NaN
回退报告),官方形状三格,与 coarse12 同会话 A/B 旧臂对比:

| 格 | 原型 | coarse12(本工具链) | 加速 | 校验 |
| --- | ---: | ---: | ---: | --- |
| b4096 V131072 k2048 | **6.134 ms** | 7.603 | **1.24×** | contract 0、set 0/64、回退 18(溢出) |
| b4096 V129280 k512 | **4.565 ms** | 6.486 | **1.42×** | 全过,回退 0 |
| b4096 V107520 k2048 | **5.285 ms** | 6.600 | **1.25×** | 全过,回退 123(3% 溢出) |

相位(ms/row,旗舰):sample 0.009 / filter 0.097 / refine 0.046。
**剩余杠杆(按预期排序)**:OUT=2 行走(复基准 966-1232)、ballot 压缩
消单计数器(→ ~1150 估)、按形状修裕量(12-bit 阈值的候选 ~2500-3300,
V107520 有 3% 溢出;1.25k 裕量或 20-bit 阈值可压回)。

## 5. 迭代(pod 32741,2026-10-21)

- **OUT=2 过滤行走(落地)**:旗舰 6.134→**5.421 ms**(filter 0.097→
  0.075 ms/row)、k512 4.565→**4.066**、V107520 5.285→**4.685**;
  对 coarse12 比值升至 **1.40× / 1.60× / 1.41×**(后者为 pod 30752 的
  A/B 旧臂值;跨 pod 比值仅作参考)。
- **ballot 压缩暂存(实测否决)**:寄存器批 + 波扫描 + 每波 1 原子,
  每行 tick 降(0.133→0.123 ms)而墙钟升 79%(5.42→9.72)—— `int my_idx[8]`
  的 +8 寄存器把占用打低;换 8-bit 掩码(+1 寄存器)仍 6.97 不敌单计数器。
  **幸存率 2.3% 时单计数器的原子已经够稀,扫描开销 > 省下的原子** ——
  与复基准"fp32 原子不构成约束"同向。回退到单计数器 OUT=2。
- **溢出回退的生产设计**(消除两种回退):T12 地板欠收结构性不可能
  (count(>T12) ≥ 桶人口+上方计数 ≥ ~1400,k512 上实测回退 4→0);
  溢出(staged > 4096)时做**第二轮 20-bit 阈值精化重走**(代价仅落在
  溢出行 ~0.4-3%),不再回退 coarse12。

**踩坑记录**(全部已修,按发现顺序):
1. 精化漏了 12-bit 层级(候选跨多个 12-bit bin,4 轮 8-bit 从 off=24 起
   才对)——首版 3 轮从 off=12 起,全错。
2. thread-0 串行 256 桶后缀扫描 = ~76 µs/row(首个 9.3 ms 的主因之一)
   → 并行 suffix256 + find_crossing(256 线程一票)。
3. suffix256 的 Hillis-Steele 链**必须带 lane 卫**:MACA 的
   `__shfl_down_sync` 越界读返回**本 lane 当前值**,无卫时 lane63 每步
   翻倍(实测 h[255] = 64137 vs 期望 255;dsa_topk 的
   `run_cumsum_warp` 带同款卫 `lane + i < kWarpSize`,独立印证)。
4. scratch 2048 < round-0 边界(~1400-2900)→ 溢出型回退 100%;
   4096(= kCap)使溢出结构性不可能。
5. T 的移位:`bin12 << 20`(12-bit bin = key>>20),一度误写 `<< 12`
   (旧 20-bit 形式的残迹),全行 staged。
6. NaN 谓词的 `|=` 拼写在该工具链上误触发(换 `if` 形式即消失 ——
   与 L2 `__forceinline__`、uint4-by-value 同一族的工具链敏感性)。
7. 驱动/内核计数器宽度不一致(8 vs 12)= 内核越界写 + 驱动错位读,
   表现为假 NaN 计数 1367。教训:**两侧宽度同一处定义**。
