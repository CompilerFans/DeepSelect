# bf16 块直方图摘要走查:每组走四个**相邻**块(2026-10-21)

设备:MetaX C600-U(28 AP,family 1600,MACA 3.8.1.3,device 1)。改动只在
`csrc/maca_kernels/common/radix_row_bf16.cuh` 的 `summary_walk` 里
`kHist == false` 那一支——也就是 `095224c` 的块直方图臂的 pass 1。

本目录:`walk3.cu` / `walk4.cu` / `walk5.cu` / `walk6.cu`,四个独立微基准。
全部在**真实形状**上跑:4096 行 × 1048576 bf16(8.59 GB),一行一个 CTA,
BLOCK 1024,每个臂打印 `cudaOccupancyMaxActiveBlocksPerMultiprocessor` 的答案,
三轮取最好。`GB/s = 行数 × V × 2 B ÷ 时间`。

微基准是独立核,不是内核内消融:扰动直方图的核内消融会让阈值移动、collect
写过槽位,换来 `Memory Violation(0x4)`(块直方图实验里已经踩过)。

## 0. 目标相位

`docs/experiments/20261021_blockhist/` 的相位表:b4096 V1048576 k512 上
**hist1a(块最大值 walk)= 574,704 周期 = 73%**,k1024 上 80%。in-situ 速率
8.59 GB / 10.4 ms ≈ **826 GB/s**,是 1545 GB/s 读墙的 54%。这一格就是
12768.9 us 里最大的一项,所以先动它。

## 1. 它不绑在树、变换、原子或 MLP 上

`walk3.cu`,BLOCK 1024,occ 2 CTA/SM:

| 臂 | 做什么 | GB/s |
| --- | --- | ---: |
| FULL2 | 生产形态:有序键变换 + 每线程 8 元素 max + 3 步 bpermute 树 + lane0 存块最大值 + 每块 1 次原子,每组 2 块(步长 `step`) | 858.6 |
| ONE1 | 树只走 1 步(答案错,只用来给树的开销定上界) | 822.6 |
| RAW2 | 去掉有序键变换(答案错) | 874.7 |
| FULL4 | 同样步长形态,每组 4 块在飞(MLP 杠杆) | 673.6 |
| B128 | 每 128 元素一块(树/存/原子率减半) | 1073.4 |
| FULL2@512 | 同上,BLOCK 512 | 649.1 |
| FULL2@256 | 同上,BLOCK 256 | 355.4 |

四条读法:

- **树不是开销**:ONE1 只比 FULL2 低 4%(三步合一步,还少 2/3 的 shuffle)。
- **变换不是开销**:RAW2 与 FULL2 同速。
- **原子不是开销**:walk4 的 FULL2A(去掉每块一次原子)842.5,与 865.2 同噪;
  B128A(原子率减半)1067.7 与 B128 1067.9 一致。
- **MLP 也不是**:同形态下 4 块在飞(FULL4)反而慢 22%。

所以慢的是**地址**:步长形态一次迭代摸两块,两块相距 `step × 64 × 2 B = 16 KB`
(BLOCK 1024);而 B128 一次摸两个相邻 uint4,快了 24%。

## 2. 相邻性就是那个变量

walk4 / walk5:同样的树、同样的存、同样的原子,只把一组负责的块从
`(g, g+step, …)` 换成相邻块。

| 臂 | BLOCK 1024 | BLOCK 512 |
| --- | ---: | ---: |
| FULL2(步长,2 块/迭代) | 861.7 | 644.7 |
| ADJ2(相邻 2 块) | 1035.9 | 942.6 |
| ADJ2P(相邻 2 块,两个 uint16 合成一次 uint32 存) | 1044.3 | 958.1 |
| ADJ2S(相邻 2 块,不存块最大值) | 1172.6 | — |
| **ADJ4(相邻 4 块)** | **1295.6** | **1329.6** |
| ADJ4P(ADJ4,两对打包存) | 1301.5 | — |
| ADJ4S(ADJ4,不存) | 1338.4 | — |
| ADJ8(相邻 8 块) | 859.7 | — |
| B256(256 元素一块) | 934.8 | — |

三点:

1. **1.50× 来自相邻本身**:ADJ2 已经 +20%,ADJ4 +50%;打包存(ADJ2P/ADJ4P)与
   不存(ADJ2S/ADJ4S)都只再动 1–4%——存不是问题,存的**地址分散**才是。
2. **8 块过头**:ADJ8 掉回 FULL2 的水平(寄存器/调度爆掉,occ 仍报 2)。
3. **BLOCK 512 上 ADJ4 更赚**(1330 vs FULL2 645,2.06×),所以形态按 BLOCK 参数化,
   没有常数假设。

BLOCK 1024 的 ADJ4 用 42 MT 寄存器(独立核),occ 2——真实核见 §4。

## 3. 稠密臂(kHist = true)不要动

块直方图臂只覆盖 `topk <= length/256` 的格子;门下的格子走的是**每元素一次
共享原子**的稠密 walk。walk6 在同一形状上量了它:

| 臂 | GB/s |
| --- | ---: |
| HIST_FULL2(生产形态,步长) | 559.2 |
| HIST_ADJ4(相邻 4 块) | 535.6 |

相邻在稠密臂上**更慢**(它受共享原子发射率限制,地址不是瓶颈;相邻反而让同一
波内 8 个 lane 的原子更集中)。所以改动只落在 `!kHist` 一支,门下格子按构造
不变——这也是 A/B 里的对照组。

## 4. 覆盖算术(每个 64 元素块恰好一次)

相邻 4 块要求每组的块编号是 `4g, 4g+1, 4g+2, 4g+3`,步长 `4*step`:

```
group g 的第 i 次迭代:块 [4g + 4*step*i, +4)
```

- 主循环条件 `blk + 4 <= nblk` ⇒ 每组在最后一轮里只有 `g < nblk/4` 的组拿到整块,
  覆盖恰好 `[0, nblk - (nblk % 4))`。
- 余下 `s = nblk % 4`(0..3)块由 `g < s` 的组各走一块(`nblk - s + g`)。

**`blk` 必须从 `4*group` 起**,不是 `group`:后者让相邻四组各自摘要一段重叠区间,
直方图变成 4 倍,阈值跟着错。这一版第一稿就是 `group`,在构建前被复查抓下来。
尾部也一样:第一稿让"下一段会跨过行"的组各走一段连续块,`nblk % 4 != 0` 时
边界两块会被 `g = q-1` 和 `g = q` 各数一次。

官方网格是 2 的幂,`nblk % 4 == 0`,尾部根本不跑;会踩尾部的是"长度不是 2 的幂"
的格子,由 `tests/test.py` 的抽样和 `tailprobe.py`(本目录)覆盖:
长度 2048..2240 每 64 一档,`nblk % 4` 取 0/1/2/3,块直方图臂和稠密臂都跑,
按契约(`min(selected) >= max(unselected)`、下标范围、唯一性、值/下标配对、
`sorted_index` 有序)检查。

## 5. 寄存器与占用

单 TU 实测(cucc `--resource-usage`,xcore1600;数值是该 TU 里 bf16 行实例
`topk_kernel_radix<...>` 的最大值,静态 smem 两档都是 4936 B):

| TU | HEAD | 本改动 |
| --- | ---: | ---: |
| `value_bf16_outidx_i32_block_1024_si0_rv0_sv0_pre0.cu` | 50 MT / 64 ST | 66 MT / 64 ST |
| `value_bf16_outidx_i32_block_512_si0_rv0_sv0_pre0.cu` | 50 MT / 64 ST | 66 MT / 64 ST |

+16 MT 是三个额外 uint4(12 个寄存器)加簿记。(本文早先记的"48 → 62"是
block_1024 TU 里 `pre0`/k512 那一个符号的读数;TU 的最大值两档都是 50 → 66。)

**占用没有掉,而且这是问驱动问出来的,不是手算的。** 同一支探针
(`cudaOccupancyMaxActiveBlocksPerMultiprocessor`,动态 smem 由
`radix_smem_bytes(topk, false, true)` 给出)在两棵树上各跑一遍,pre0/pre1
两支都在内:

| 配置 | 动态 smem | HEAD | 本改动 |
| --- | ---: | ---: | ---: |
| BLOCK 512, k512 | 18432 B | 4 | **4** |
| BLOCK 512, k1024 | 20480 B | 4 | **4** |
| BLOCK 1024, k512 | 18432 B | 2 | **2** |
| BLOCK 1024, k1024 | 20480 B | 2 | **2** |

旗舰格(b4096 的长行)按 `radix_block_for` 走 BLOCK 512,常驻仍是
4 CTA/SM;BLOCK 1024 那档也没动。注意 66 MT 按
`66 × 512 = 33792 > 131072 / 4 = 32768` 手算会得出 3,而驱动答 4——所以这里
记的是驱动的答案,不是除法的答案。

## 6. 核内 A/B

`tools/ab_snapshot.py`,同一 session 内两臂交替,每格 3 轮 × 10 迭代,取
每轮中位数再配对(比值 = new / old,< 1 表示新臂更快)。官方形状:
`abort_when_nan_found=False`(`check_nan` 仍为默认的 True)。device 1;

```bash
python3 tools/ab_snapshot.py \
  --arm old=/tmp/arm_518 --arm new=/root/github/DeepSelect \
  --snapshot perf_data/MetaX_C600-U/20261021_032150 \
  --rounds 3 --device 1 --abort-when-nan-found no --out /tmp/ab_adj4
```

三件事:

- **BH 格子全部前进,且按 V 排序**:V=1M 的 0.845–0.880,V=512K 的
  0.868–0.920,V=256K 的 0.926–0.938。行越长,摘要 walk 在整格里的占比越大,
  收益也越大——与 §0 的相位表一致。
- **对照组不动**:4 个稠密格(-3.1%..+1.5%)与 3 个长度 1024/16384 的格子在
  噪声内;fp32 的 c12/split 两条路由 10/16 格全部在 ±1.4% 内,这一支根本不在
  改动范围里,是同一 session 的稳定性证据。
- **核内步长比微基准小**:整格 1.17×(12762.6 → 10927.3),按 §0 的 hist1a
  占 73% 反解,walk 本身约 1.25×(826 → ~1030 GB/s),而独立核 ADJ4 是 1.5×
  (870 → 1295)。差的这一截是微基准没有的东西:生产 walk 每个 uint4 多一次
  真 NaN 谓词(`kNan` 默认开),外加 `kSkip` 的块列表/摘要簿记。微基准给的是
  地址序能买到多少的上界,不是整格能兑现多少。

因此这个改动的 roofline 判词是**地址局部性**:它不是浮点、不是树、不是原子、
也不是 MLP——相邻四块在行内是连续 512 B,BH 格子的整格速率从 673 GB/s 抬到
786 GB/s(1545 GB/s 读墙的 44% → 51%,其余是 pass 2 与 collect)。
