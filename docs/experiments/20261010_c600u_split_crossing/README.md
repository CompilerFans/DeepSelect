# C600U 的 split 交叉点：batch 随 sqrt(vocab) 长，不是随 vocab（2026-10-10）

一句话：C500 的 `kChunkedVocabPerRow = 21000` 是「过原点的直线」，在 C600U 上过宽 ——
b=8..24 的格子里 split 比 row 慢 1.06–2.2 倍（`524288 x b24`：208.9 vs 101.8 µs，**2.05x**）。
C600U 自己的交叉是 ~6.7 / 9.3 / 12.7（vocab 262144 / 524288 / 1048576，k512/k1024 相差
≤1.5），随行长每翻倍只涨 ~1.36x；直线拟合的最好最差 regret 是 1.30，sqrt 形
`b² · 6400 ≤ vocab`（阈值 6 / 9 / 12）是 **1.008**。换过去之后每个 band 格都走更快的一条。

## 1. 为什么 C500 的常量在 C600U 上过宽

- C500 的 gate 是 `batches <= vocab / 21000`（阈值 12 / 24 / 49），它自己的交叉
  19.4 / 29.4 / 43.5 也不是直线能穿过的，21000 是「最好最差」的那个拟合（其注释自述）。
- C600U 的机器不同：28 AP、行核 1024 线程 2 CTA/SM（C500 是 1），split 的
  `chunked_chunks` 在 28 AP 上按波填成 18。交叉因此落在更小的 batch，且形状更"弯"。
- 官方网格**不受影响**：`b ≤ 64` 的格只有 b = 1 / 6 / 64 —— 1 和 6 两条规则都进 split，
  64 两条都不进。这一笔是给 decode 形状（b=8..24、vocab ≥ 256K）的路由修正，不是网格数字。

## 3. 形状：直线不行，sqrt 行

- 过原点直线 `b ≤ v/K` 的最好最差 regret 是 **1.299**（K=53000–65000，绑定格是
  `1048576 x b16` k512：split 慢 1.30x）。K 再大则开始丢 `262144 x b4`（1.26）这类赢。
- sqrt 形 `b² · 6400 ≤ vocab`：阈值 6 / 9 / 12，对三个交叉的最大偏差 0.7 batch；
  在这 56 格上 **realized ≤ 1.008**（唯一贴边的 `1048576 x b12` k1024 = 0.992）。
- 机制上也讲得通：split 的时间随 b 线性（每行固定成本），行核在填满一波前对 b 是平的；
  两者相交的 b* 随着 v 涨，但比 v 慢得多（行核的平段时间本身是 v 的次线性函数）。

```cpp
constexpr uint32_t kC600UChunkedVocabPerBatchSq = 6400;
// chunked_bf16_applies(...)：is_c600u_ap_count(sm) 时
//     return batches * batches <= params.vocab_size / kC600UChunkedVocabPerBatchSq;
```

C500（104 AP）路径逐行不变；`batches ≤ 64` 保证平方不溢出。
