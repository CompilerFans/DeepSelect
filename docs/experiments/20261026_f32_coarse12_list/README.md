# fp32 Sampler 行的相位表,以及块表读批量化:4 个 c12 格一致 −1.4~−2.3%(2026-10-26)

设备:MetaX C600-U(28 AP,family 1600,MACA 20261017.1436),设备 1,
源码 `d9704cb`,产物 `8a4c3501970c`(对照臂)、`dc10e7527d0a`(改动臂)。

`f32phase_patch.py` 把 `clock64()` 计时器插进 `topk_coarse12.cuh` 的**副本**
(每个锚点断言唯一),`f32phaseprobe.cu` 直接调用 `topk_coarse12_row`,一行一 CTA、
1120 行正态数据、先爬频 300 次再计时(与 bf16 那份探针同一口径)。

## 0. 结论

1. **Sampler 路径(b≥256 走 `topk_coarse12_kernel`)的相位表**:V=129280 k512 时
   pass 1 **62.2%**、保块列表 **13.9%**、pass 2 17.3%、精化 3.9%、扫描 2.8%;
   V=262144 时 pass 1 69.5%、列表 **15.7%**、pass 2 9.8%。
2. **pass 1 已经在自己的天花板上**:5.07 B/cycle/CTA(bf16 的走查是 5.9)。
3. **保块列表是这条路径上唯一明显低效的一段**:8,081 个 `uint16` 表项(16 KB)
   花了 22,763 cycles,**0.7 B/cycle** —— 一次依赖读的串行链,不是走查。
   bf16 在 `20261026_table_batch` 已经用"批读 4 宽"修过同一件事,fp32 这条没修。
4. **批读 4 宽落地:四个 c12 格一致 −1.4~−2.3%**(配对 A/B,3 轮,两臂的
   `lib` md5 由子进程自己打印),其余 108 格是噪声。列表相位 22,763 →
   17,064 cycles(−25%)。

## 1. 相位表

`cycles/行`,整行 = 164,039(V=129280)/ 353,187(V=262144),时钟 1.82/1.86 GHz
(由 whole/墙钟反推);占用率由驱动回答:**3 CTA/AP**(84 并发,16 KB 动态共享)。

| 相位 | V=129280 | % | V=262144 | % |
| --- | ---: | ---: | ---: | ---: |
| pass 1(4,096 桶直方图 + 块最大值 + NaN 票) | 101,952 | 62.2 | 245,424 | 69.5 |
| 扫描(256 桶折桶 + cumsum + 12 位窄化) | 4,663 | 2.8 | 4,644 | 1.3 |
| **保块列表** | **22,763** | **13.9** | **55,456** | **15.7** |
| pass 2(走列表收集) | 28,334 | 17.3 | 34,766 | 9.8 |
| 精化(竞技场三轮) | 6,328 | 3.9 | 12,897 | 3.7 |

与此前记过的两份表对照:

- **pass 1 的 5.07 B/cycle 说明它已接近读墙的上限**(bf16 摘要走查 5.9,
  这里是 fp32 键变换 + 每元素一个共享原子)。
- **pass 2 的散列地板与 bf16 同价**:c12 的块是 16 个 float(64 B),保留率约 7%,
  每个保块一次 64 B 取回,与 `20261026_row_phases2` §3 记的"每块 65 cycles"同形。
- **列表这一段没有对应物**:bf16 的块表是每 64 元素一项,fp32 是每 16 元素一项,
  所以同一份表的读取在这里贵 4 倍。

## 2. 改动与 A/B

`topk_coarse12.cuh` 的保块列表循环,一次读四个表项再逐个判定:

```cpp
        for (; b + 3 * kThreads < nblk; b += 4 * kThreads) {
            int m[4];
            #pragma unroll
            for (int i = 0; i < 4; ++i) m[i] = static_cast<int>(block_max[b + i * kThreads]);
            #pragma unroll
            for (int i = 0; i < 4; ++i) {
                if (m[i] < wide_threshold) continue;
                block_list[atomicAdd(&kept_block_count, 1)] = ...;
            }
        }
```

列表的顺序会变(原子追加),但 pass 2 只把它当集合用,答案不变。

`tools/ab_snapshot.py --arm base=/root/ab_base2 --arm f32list=/root/ab_f32list
--snapshot perf_data/MetaX_C600-U/20261026_052535 --rounds 3 --device 1
--abort-when-nan-found no`,122 格、两臂交替、每臂每轮 10 次:

| 路由 | 格数 | 中位 | 范围 |
| --- | ---: | ---: | --- |
| `c12`(fp32 Sampler) | 4 | **0.9850** | [0.980, 0.986] |
| `row`(bf16) | 95 | 1.0020 | [0.990, 1.086] |
| `split` | 13 | 0.9989 | [0.986, 1.020] |

逐格(三轮最小值):

| 格 | base | f32list | 比值 | GB/s |
| --- | ---: | ---: | ---: | --- |
| b512-v129280-k512 | 496.8 µs | 485.5 | **0.9772** | 432 → 442 |
| b768-v129280-k512 | 722.2 | 707.3 | **0.9793** | 450 → 460 |
| b256-v129280-k512 | 272.3 | 267.3 | **0.9816** | 390 → 397 |
| b4096-v129280-k512 | 3639.8 | 3589.4 | **0.9861** | 476 → 483 |
| b6-v129280-k512(split,不经过这段) | 52.9 | 52.5 | 0.9908 | 噪声 |

bf16 的 95 个 row 格与 13 个 split 格不动,说明改动的边界就是这段循环。

## 4. 边界

- 改动在 `csrc/maca_kernels/common/topk_coarse12.cuh`,三个 family 的产物都会变;
  只在 xcore1600(C600-U)上构建和测量,xcore1000 / xcore1500 未构建、未测量。
- 相位表只测了 fp32、k=512、V=129280/262144 两档;`topk_coarse12_row` 的
  `b<=2` chunks 路由与 row 路由未测。
- pass 1 / pass 2 的成因(键变换成本、散列地板)与 bf16 那两份记录的结论同源,
  不在这里重复测。
