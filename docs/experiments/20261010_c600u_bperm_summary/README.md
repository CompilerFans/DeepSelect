# C600U pass 1 的消融，与 summary 走 permute 的一笔（2026-10-10）

**一句话**：C600U 行核现在 = pass 1 的 **84.5%**（相位标记实测）+ collect 一小截；
把 pass 1 拆开消融后，**共享原子 ≈ 19%、块内 max 摘要 ≈ 25%**（两者合计 28%，亚可加）；
摘要里的 3 次 `__shfl_down_sync` 包装是它的大部分成本，换成平台自己的
`bsm_bpermute` 三步树（语义逐位相同，`block_max` 哈希一致）后 pass-1 走法
**524 → 645 GB/s（+23%）**，已落地生产核并按下表重测。

## 1. 相位（内核自己的标记，`probe_phase_marks.py` 打在丢弃树上）

    4096 x 1048576 k512: clear 0.2% | pass1 84.5% | threshold 0.9% | compact 5.9% | collect+emit 8.4%
    4096 x 524288  k512: pass1 75.2% | threshold 1.7% | compact 5.5% | collect+emit ~17.6%
    768  x 1048576 k512: pass1 84.5% | ...

即：**`_b` 已经基本是 pass 1 一趟**（skip 清单把 collect 压到 ~6%），所以 pass 1 的每
AP 吞吐就是这只核的天花板。折算：pass 1 = 569 GB/s 机器级 = **20.3 GB/s/AP**（每 AP 墙的 37%）。

## 2. 消融（`pass1_walk.cu`，4056 行 × 1M × 2 趟，三轮，单位 GB/s 机器级）

| 臂 | GB/s | 读法 |
|---|---:|---|
| full（= 生产核的 pass 1 形状） | 521 | 与相位折算的 569 同量级 ✓ |
| − 直方图原子（`noatomic`） | 642 | **原子 ≈ 19%** |
| − 块 max 摘要（`nosummary`） | 699 | **摘要 ≈ 25%**，去掉后落在裸载入地板 |
| − 两者（`nosummary_noatomic`） | ~725 | 合计 ≈ 28%（亚可加：两者都碰发射口） |
| bare（只载入） | ~720 | 走法的地板 ≈ 47% 墙 |
| full + unroll 2 / 4 | 520 / 532 | **展开无收益 ⇒ 不是 MLP 受限，是发射受限** |

两条推论：**（a）** 墙要 27.6 GB/s/CTA（2 CTA/SM），地板只有 ~26 GB/s/AP ⇒ 这个走法
结构本身就在 ~47% 墙附近封顶；**（b）** 剩下的都在"每元素算术"里，其中摘要的
shuffle 包装是最大的一块。

## 3. summary 换 `bsm_bpermute`（本轮落地）

平台自带的 `__shfl_*_sync` 是"一条原生 shuffle + ~5 条索引/宽度算术"（CLAUDE.md
自己的表：5 步扫描 71 对 44 条指令），而这段算术不会被提出循环。摘要的树是
链式三步（mask 在 MACACC 下是 `0xFF << (tx & 0x38)`），完全可以写成
`bsm_bpermute(((tx + d) & 63) << 2, key)`：

- **不需要 mask**：只有 lane 0 的结果被读，且 `(tx+d)&63` 只把值往 *下* 带 ——
  组边界的"污染"最多进到 lane 5/7，而 lane 0 的链（0,1,2,4）永远读不到它们。
- **语义逐位相同**：两臂的 `block_max` 全表 FNV 哈希一致
  （`9422c4c9c656eedc`，见 `ablation_raw.txt` 的 `bmax hash` 行）。

实测（同 bench，4096×1048576×2 趟，三轮）：

| 臂 | GB/s |
|---|---:|
| full（shfl 摘要） | 524.0 / 524.1 |
| full + bperm 摘要 | **633.9 / 651.8** |

## 4. 生产核落地与验证

配对 A/B（copy-and-point，两轮交替，种子固定；新树 md5 `962b5883` vs HEAD `3ec78e0b`）：

| 格 | 旧 µs | 新 µs | 比 | 旧 GB/s | 新 GB/s |
|---|---:|---:|---:|---:|---:|
| 4096 x 1048576 k512 | 17888.8 | 16814.2 | 0.940 | 480.2 | 510.9 |
| 4096 x  524288 k512 |  9573.2 |  9002.1 | 0.940 | 448.8 | 477.3 |
| 768  x 1048576 k512 |  3484.2 |  3283.0 | 0.942 | 462.4 | 490.8 |
| 4096 x   65536 k512 |  2163.8 |  2139.9 | 0.989 | 248.4 | 251.1 |
| 4096 x   16384 k512 |   787.4 |   787.1 | 1.000 | 对照：该格无摘要 |

（bench 里 pass-1 走法 +23% 到生产核只剩 −6%，因为摘要在真核里占 ~21% × 84.5%。）

寄存器：行实例 36–39 → **44 MT**（`--resource-usage`）——C600U 上 2×1024×44 ≤ 131072
仍是 2 CTA/SM；C500 本来就 1 CTA（36–39 已 >32），不动占用率。

正确性：`block_max` 表在两臂逐位一致（FNV 哈希同）；变化路径 + 对照格过官方
`run_testcase`（见提交记录）。

## 5. 下一步候选（按本轮实测排序）

1. **原子（19%）**：平台共享原子≈1 拍，warp 聚合已多次被证否（本仓与 handover §9
   "别做"）；剩下的形状只有 register-then-flush，但其"索引 `(key>>4)&15`"在文档里
   是未定义的（不是合法直方图），要做就得先定义清楚再量。
2. **走法地板（47% 墙）**：展开无效、单载入 16 B/线程固定 —— 想再往上要么换数据流
   （handover §9 第 1 条），要么等平台给出更宽的载入。
3. **NaN 检查**：`check_nan=False` 在 C600U 上值 5–6%（见
   `docs/experiments/20261010_c600u_narrow_row/` §7）——是契约开关，不是调参。
