# 保留块列表遍历:一次放四个入口,不落地(2026-10-21)

设备:MetaX C600-U(28 AP,family 1600,MACA 3.8.1.3,device 1)。旧臂 = ADJ4 产物
`281cc660`(`/tmp/arm_adj4`),新臂 = 本节改动产物 `15c2e883`。

## 0. 目标相位与假设

blockhist §9 的相位表:b4096 V1048576 k512/k1024 上 hist1b = 8%、collect = 11%。
两者都走 `walk_kept_blocks`——每个 group 迭代只取**一个**列表项,于是每个线程只有
**一个 uint4 在飞**。这与块直方图行走用"四邻块一组"修掉的是同一个内存延迟上限
(`docs/experiments/20261021_adjacent_walk/`:1/2/4 在飞 = 265/956/1,390 GB/s,
单 512 线程 CTA/SM)。相位表说这两段读行内 ~6% 的字节却占 19% 的时间——延迟,不是流量。

改动:`walk_kept_blocks` 每轮先取 `j, j+stride, j+2*stride, j+3*stride` 四个列表项的
地址与 uint4(背靠背发出),再逐个消费;标量尾巴保留原形。覆盖不变,顺序无关。

## 1. 测量

官方形状(`indices_type=int32`、`return_value=False`、`abort_when_nan_found=False`)。
两个臂各起一个进程(不同 `PYTHONPATH`),交替顺序,每格取 11–15 次中位。

| 格 | 旧 | 新 | 比值(新/旧) | 轮次 |
| --- | ---: | ---: | ---: | --- |
| b4096 V1048576 k512 | 11.11 / 11.13 | 11.17 / 11.12 | **1.0054 / 0.9991**(中位 1.0022) | 2(反序) |
| b4096 V1048576 k1024 | 12.58 / 12.56 | 12.63 / 12.56 | **1.0040 / 1.0000**(中位 1.0020) | 2(反序) |
| b4096 V 262144 k512 | 4.552 / 4.497 | 4.517 / 4.531 | 0.992 / 1.008(中位 1.000) | 2(反序) |
| b4096 V 262144 k1024 | 5.855 / 5.851 | 5.834 / 5.836 | 0.996 / 0.997(中位 0.997) | 2(反序) |

**没有收益**:旗舰格两轮反序的中位是 **+0.2%**(略慢),第二轮的符号翻转正说明
剩下的差值就是会话噪声;19% 的相位连 1% 都没动。V262144 两轮符号也相反
(k512 一轮 −0.8%、反序一轮 +0.8%),同样落在噪声里。

## 2. 为什么

与 `docs/experiments/20261021_list_build/` 同一个原因,而且这次不是微基准、是核内:
**列表指向的块刚刚被 hist1a 读过**——同一个 CTA 在 pass 1 里顺序走过整行并写下
`row_block_max`,紧接着的 hist1b/collect 只重读其中 ~6% 的块,那些块几乎必然在
L2 里。walk 于是不是"内存延迟受限",而"一次只有一个 uint4 在飞"在 L2 命中下
本来就不是瓶颈。四个入口只是多活了 3 个 uint4(+12 MT 级寄存器)和更长的
scoreboard,换不到延迟。

相位表里 hist1b+collect 的 19% 因而不是延迟预算,而是**逐元素工作**(键变换 +
共享原子)——与 `20261021_nan_cost/` §2 的结论一致:每元素一条 ALU 的测试已经
是地板,它们的价签在指令发射,不在访存。

## 3. 结论

**不落地。**改动本体见 `list_walk4.patch`(`git apply --check` 已验证)。产物
`15c2e883` 留在 `.arm_listwalk4/` 下,方便复测。正确性:新产物上契约自测 6/6
(v = 4096/65536/262144 × k = 512/1024,V=262144 两格走块直方图臂,即被改的
walk),唯一性与 `min(selected) >= max(unselected)` 全过。

复测注意:pod 上 `develop.sh` 会 `rm -rf build`,每次都是 90 个 TU 的全量编译
(共享机上 15–25 分钟);V1M 的 randn→bf16 数据生成约 25 s/进程,输入种子固定为
11(V1M)/12(V262144)。
