# C600U 长行块宽：batch ≥ 256 之后窄行（512 线程实例）接管（2026-10-10）

一句话：`needs_long_row_bf16` 的 60000 交叉点是**在 C500 上量的**（它自己的注释就这么说），
在 28-AP 的 C600U 上它把**全部长行**送进 1024 线程实例；而这些格恰好是 C600U 相对 C500
最慢的格（比值 1.8–2.2，短行只有 1.3–1.5）。改成「batch 自己就能填满这台机器之后走窄行」
（`kC600UNarrowRowBatches = 256`）后，官方网格 **−4.7%**（153.8 → 146.6 ms），
`4096 x 65536 k512` 一档 **−17.7%**。

## 1. 为什么盯块宽

- 代码侧：`maca_topk.cu` 的 `radix_block_for` 决定 bf16 行核用 512 还是 1024 线程实例，
  依据是 `radix_core.cuh` 的 `needs_long_row_bf16`（`L ≥ 60000`、`B ≤ 4096`、
  `topk ∈ {512,1024}`）。它的交叉点注释自述「specific to the 16 KiB C500 row variant」。
- 机器侧（本机实测）：C600U 28 AP × 2048 线程，**`regs_per_multiprocessor = 131072`**
  —— C500 的两倍（65536）。行核带跳过表是 36–39 MT，于是 1024 线程 CTA 在 C600U 上
  **2 CTA/SM**（C500 上 1 个）。同为 100% 线程占用时，窄行给 AP 的是 4 个独立 CTA，
  宽行只有 2 个。
- 网格侧：C600U/C500 的逐格比值随 batch 上升 —— 短行（L < 60000，已走 512 实例）
  1.26–1.48；长行（走 1024 实例）b64 起 1.5，skip 区 1.8–2.2。

## 2. 测量方法

copy-and-point A/B（与 split 交叉点同一套）：每个臂一份树、只改一处，
一轮一个进程、交替进行、种子固定，计时用 `tests/test.py` 自己的规则。

    b512    radix_block_for 恒回 rk::kBlockSize (512)
    b1024   B<=4096 且 k∈{512,1024} 恒回 rk::kLongRowBlockSize (1024)
    parent  原样（长行走 1024）

原始表：`block_width_raw.txt`（三轮扫描）。子进程打印实际 launch 的行核名，
所以「臂真的换了实例」是输出里的字据：

    parent: ...topk_kernel_radix<__maca_bfloat16, int, 1024, ...>
    b512:   ...topk_kernel_radix<__maca_bfloat16, int,  512, ...>

## 3. 交叉点（ratio = 窄行/宽行，<1.0 是窄行赢）

     vocab    65536  131072  262144  524288  1048576
     b 64      0.97   1.03    1.07    1.09    1.10
     b 128     0.95   0.99    1.02    1.04    1.05
     b 192     0.91   0.97    1.00    1.01    1.03
     b 256     0.90   0.93    0.98    1.00    1.00
     b 4096    0.83   0.87    0.93    0.96    0.97

交叉的 batch 随行长抬升（65536 约 45，1048576 约 270），所以**没有一条单值折线能穿过全部行**；
256 是"窄行在**每一个**实测格上都赢"的最小 batch（最差 1.004、最好 0.826）。
256 以下保留宽行，因为窄行的亏都堆在那里（`b1..b6` 处 1.37，`64 x 1048576` 处 1.10）。

短行一侧：`b1024` 臂在 `4096 x 16384 / 4096 / 1024` 上分别是 1.41 / 1.73 / 1.82，
即短行继续走 512 是对的（这一侧规则没动）。

## 4. 规则与实现

```cpp
inline constexpr uint32_t kC600UNarrowRowBatches = 256;
inline bool is_c600u_ap_count(uint32_t sm_count) { return sm_count == 28 || sm_count == 32; }

// radix_block_for(...)：长行 && is_c600u_ap_count(sm) && batches >= 256 → kBlockSize
```

- C500（104 AP）路径**逐行不变**——新分支只在 28/32 上开。
- `is_c600u_ap_count` 是原来 fp32-coarse12 门里那个谓词的提级（同一集合，现在两处共用一个名字）。

## 8. 复现

```bash
python3 probe_block.py --arm parent=<树> --arm b512=<树> --arm b1024=<树> --rounds 3
python3 probe_land.py  --arm base=<HEAD 树> --arm new=<落地树> --rounds 3
python3 probe_nan.py   --tree <落地树> --rounds 3
```

臂树各是一份 `git archive HEAD` 解包 + 一处补丁 + `CUCC_TARGETS=xcore1600 python
setup.py build_ext --inplace`；`probe_nan.py` 不需要臂树（两个开关都是调用参数）。
