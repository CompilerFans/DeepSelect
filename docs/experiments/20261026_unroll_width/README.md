# 保留块走查的展开宽度:unroll 1 落地(−0.35%),unroll 4 否证(+0.86%)(2026-10-26)

设备:MetaX C600-U(28 AP,family 1600,MACA 3.0.1436.20261017,
torch 2.10.0+metax20261017.1120),设备 1,同一 pod 同一时段。三个产物只差
`radix_row_bf16.cuh` 里 `walk_kept_blocks` 的一行 `#pragma unroll N`:

| 产物 | 臂 | md5 | 大小 |
| --- | --- | --- | --- |
| A | `#pragma unroll 2`(改动前,`100cc9b`) | `8759bb529d87` | 20,643,224 B |
| B | `#pragma unroll 4` | `771e4b08d671` | 25,095,576 B |
| C | `#pragma unroll 1`(落地) | `76fb2653` | 18,394,520 B |

每个产物用 `CUCC_TARGETS=xcore1600 ./develop.sh` 单独构建,同一脚本交替跑
`python tests/test.py --perf-only -nc --dtype bf16`(117 格,先校验后计时)。
每个比较跑 4 轮(A、B 各两轮;A、C 先 A 后 C 两轮,再 C 先 A 后两轮),
各格取两臂的最小值。**8 次网格全部 117/117 通过**,0 check_fail,0 crash。

## 0. 结论

1. **unroll 1 落地:网格 82,759.8 → 82,445.4 µs(0.9962),全四轮 0.9965。**
   A 先的两轮 0.9962、C 先的两轮 0.9960 —— **两种交替顺序读数一致**,不是顺序效应。
   收益集中在 batch 4096 的短行:`b4096 V65536 k512` **1804.3 → 1774.2 µs(0.9833)**、
   `b4096 V4096 k512` **463.9 → 448.5(0.9669)**、`b4096 V131072 k1024` 0.9909、
   `b4096 V131072 k512` 0.9963;长行接近中性(V1048576 0.9990)。
2. **unroll 4 否证:网格 1.0086,放行闸门的 69 格 1.0065。**
   最差的就是本改动该服务的格子:`b4096 V131072 k512` **2418.9 → 2498.8 µs(+3.3%)**,
   k1024 +2.8%,V262144 两档 +2.4~+2.6%。**这条方向关闭。**
3. **三个臂的 MT 寄存器都是 52**,占用率不动;动的只有代码体积
   (20.64 → 25.10 MB 展开 4、18.39 MB 展开 1)和 ST(66 / 70 / 64)。
   所以这不是"多几个 load 在途"的故事 —— `20261025_row_walk` §1 已经量过
   4 个在途 load 就够(s3→s4 仅 +3.4%),而在 list 走查上多展开一倍
   **只是把每个携带 list 的 arm 的代码体积翻倍**。
4. 代价是一批微小格子上的布局噪声:`b6 V16384 k1024` 18.3 → 18.7 µs(+2.2%,
   四轮内各自稳定、两臂不重叠),全表网格仍是净收益。

## 3. 寄存器与栈

`mxcc --resource-usage` 对三版编译
`value_bf16_outidx_i32_block_512_si1_rv0_sv0_pre1.cu`:

| 臂 | MT | ST | 栈 | 静态共享内存 |
| --- | ---: | ---: | ---: | ---: |
| A(unroll 2) | 52 | 66 | 0 B | 2604 B |
| B(unroll 4) | 52 | 70 | 0 B | 2604 B |
| C(unroll 1) | 52 | 64 | 0 B | 2604 B |

MT 三臂相同,所以占用率不是变量;展开宽度在这里换的是代码体积和调度,
不是并行度。生产 body 的相位拆分早已给出同一条结论的上半段:
4 个在途 load 就盖住延迟,再多的展开只买代码(`20261025_row_walk` §1)。

## 4. 边界

改动在 `csrc/maca_kernels/common/`,三个 family 的产物都会变;只在
`xcore1600`(C600-U)上构建和测量,xcore1000 / xcore1500 未构建、未测量。
fp32 行、chunked split、coarse12 都不包含这个 walk。
