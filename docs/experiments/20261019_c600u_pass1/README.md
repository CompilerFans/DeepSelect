# C600U pass 1 的采样化：探针、机制与一个 wave 一致性陷阱(2026-10-19)

设备:MetaX C600-U(28 AP,family 1600,MACA 3.8.1.3)。树:HEAD = 6fd3e67(L3+D2a 之后)。
探针源码:`mlp_wall.cu`(读墙×在途负载)、`hist_bisect.cu`(桶数/变换消融)、
`pass1_new.cu`(端到端 pass-1 形态消融)。全部用
`cucc -O2 -std=c++20 --offload-arch=xcore1600` 构建。

## 0. 校准测量(本机,暖机后)

| 探针臂 | GB/s | 读法 |
|---|---:|---|
| 裸读墙(56 CTA×512×OUT=2/4) | **1616-1695** | 本机读墙 ≈1650(规格 2 TB/s 的 82%) |
| 裸读 OUT=1,1 CTA/SM(512 线程) | 265 | 在途字节 = 线程数×16B,MLP×延迟封顶 |
| 裸读 OUT=2,同 grid | 956 | **OUT=2 在低占用下 3.6×** |
| 裸读 OUT=1,112 CTA | 1407 | 填满后 OUT=1 也够 |
| bf16 直方图走法(8 atomics/uint4,4096 桶,含 key 变换) | **771-832** | 共享原子发射率 ~12.5 G/s/SM 的硬顶 |
| 同上 +OUT=2 | 832-881 | +6%——原子封顶时 MLP 无用 |
| 同上但 1/8 采样原子 +OUT=2 | **1400-1630 ≈ 墙** | 采样把原子顶移出视野 |
| 现状 pass-1 形态(全量原子+块 max 摘要,OUT=1) | 556-599 | 与生产核 in-situ 一致 |
| 采样+OUT=2+摘要+NaN(=落地形态) | **~950-1000** | 摘要值 ~35%;见 §2 |

桶数(256 vs 4096)与 key 变换对原子速率**无影响**(bisect 探针,暖机第二轮):
r256=712 / x256=709 / r4096=782 / x4096=771 GB/s。冷机首轮读数偏慢至 3.3×——
本卡时钟爬升显著,**所有探针必须弃首轮**。

## 1. 机制结论

1. **bf16 pass 1 在 C600U 是共享原子发射率受限,不是带宽。** 28 AP × 12.5 G/s =
   350 G atomics/s,每元素 2 B ⇒ 700-880 GB/s 硬顶 = 墙的 ~50%。C500(104 AP)
   摊薄 3.7 倍所以从未撞到。
2. **采样是唯一活口**(与 20261018_fp8_mqa §3 的排序一致):warp 聚合、寄存器
   直方图、减桶数均被既往实测否决;采样直方图把原子数降 S 倍,天花板随之移出。
   **2026-10-21 修正:采样不是唯一一条。**本目录的探针只测过"每元素一次原子"
   与"完全不留原子"两档;省略中间那一档——**按块聚合**(每 64 元素块一次
   原子,切割仍然精确)——被漏掉了。落在 `095224c`
   (`docs/experiments/20261021_blockhist`):b4096 V1M k1024 17.42 → 14.16 ms。
   本目录其余结论(读墙、原子顶、wave 一致性、函数抽取陷阱)不受影响。
3. **MLP 与采样是乘性组合**:原子在环时 OUT=2 只值 +6%;原子移走后 OUT=2 让
   walk 贴墙。低占用 cell(b8-b64 长行)OUT=2 单独值 2-4×(每 CTA 在途字节翻倍)。

## 2. 落地形态与一个实测陷阱

落地形态 = OUT=1(首版) + 1/8 迭代采样 + 摘要 + NaN + 降低阈值的精确候补集
refine(见提交信息)。

**wave 一致性陷阱(第一次实现踩中)**:采样谓词若按 `(blk & 7)`(块号)判定,
块号是 8-lane group 跨步的 ⇒ 同谓词在每个 64-lane wave 内部分裂(8 个 group 里
只有 1 个投票),wave 两臂都执行,原子一条没少——实测 b4096-v1048576-k512
**反而 +50%**(16.9 → 25.3 ms)。改按循环计数器 `iter & 7` 判定(wave 内全部
64 车道一致)后投票真实生效。**凡按车道谓词裁剪发射型指令的优化,谓词必须对
整个 wave 一致。**

## 3. 落地形态的实测判决:**否决**(2026-10-19,两棵臂树交替)

数据流:采样直方图 → 带 4×k 余量的下调阈值 T_lo → collect 把 {key ≥ T_lo}
全部暂存进 arena(4096)→ 对暂存集做两轮 8+8 精确 refine → 检出
(`m < topk` 或 `m > arena`)则重walk全程回退精确路径。契约不破(暂存集 ⊇
top-k,refine 精确),恢复路径有界。

**第一版实现读数为净负**(逐 cell A/B,call span,种子 1234,与同树
L3+D2a 臂交替;两侧均过合同检查):

| cell | 基线 µs | 采样臂 µs | Δ |
|---|---:|---:|---:|
| b4096-v1048576-k512 | 16874-16898 | 19833 | **+17.5%** |
| b4096-v524288-k512 | 9045-9050 | 12764 | **+41%** |
| b4096-v131072-k512 | 3232-3236 | 5431 | **+68%** |
| b4096-v65536-k512 | 2186 | 3128 | +43% |
| b768-v1048576-k512 | 3342-3345 | 3989 | +19% |
| b256-v1048576-k512 | 1294-1296 | 1535 | +19% |
| b4096-v1048576-k512 (int64) | 16898 | 19884 | +17.7% |

干净的复测(iter 谓词修正版、独占重建后的 .so)与首轮读数逐格一致
(19832.7 vs 19837.1 等),且基线臂复现官方网格数(16888 vs 16759)——
两组数字都是有效的。

**挂起的根因(复盘时定位,两笔):**
1. **主凶——精确路径穿过循环底。** 重构把 narrow/collect/refine 包进了
   `for(;;)`,而精确路径的 refine 收尾臂(block B 主路)今天是**靠函数自然
   结束返回的**,没有显式 `return`——包进循环后它落回循环头,无限重跑。
   k∈{1024, 2048, 4096} 的 cell 必现挂起(k4096 走纯精确路径;1024/2048
   行经采样臂的 repair 后同样落到那里),k∈{128, 512} 因采样臂 refine 有显式
   `return` 而幸免。**"把一个今天靠隐式返回收尾的代码块包进循环"这一手本身
   就是 bug**,与采样无关。
2. 谓词初版 `(blk & 7)` 的 wave 分裂(§2)。




## 4. 附:OUT=2 pass-1 walk 的工具链陷阱(同日,C600-U/C600-A)

比采样否决更值得记录的是这笔,因为它是**会被再次踩中的那种**:

目标改动很小——pass-1 摘要 walk 每迭代装两个块(OUT=2,MLP 翻倍,
本机实测 265→956 GB/s @1 CTA/SM)。先后三种写法:

1. **v1:`uint4` 按值传入函数 + 函数内 `reinterpret_cast` 取地址** —— 错答。
   汇编对照(同一行实例 TU,main vs v1):`ldg_u16` 10→118(向量化 load 被
   打散成标量),并出现 main 里完全没有的 `max_u16`/`ashr_i16`(16 位窄化)。
2. **v2:把 bpermute 摘要树抽成 `__forceinline__` 函数** —— 错答。
   隔离探针(`maxtree_bisect.cu`,两种写法同核对比)16384 块零差异;但抽进
   大内核后 ~35% 块的摘要**偏低** 1-5 个 bin(设备上重算真值逐块证实:
   `summary < true`),skip-list 漏块,收集少发射。函数边界本身改变了编译器
   对这个 wave-permute 的调度。**教训:读其他车道寄存器的 intrinsic,不要做
   函数抽取;它的正确性依赖编译器在原位展开的调度。**
3. **v3:树写成宏(预处理器文本,与今天逐字节同形)+ 成对循环调原签名
   `hist_add_bf16_wide`** —— 全过(8 cell dup=0,contract 全过),A/B:
   b16-v524288 −9.1%,b256-1M −3.0%,b4096-1M-k512 −1.6%,b4096-262K-k1024
   −2.6%(两轮一致)。

探针:`maxtree_bisect.cu` / `pair_bisect.cu`(后者含 __ldg + 4096 桶原子 +
双树,均 0/8192 差异)——隔离探针全绿而就位失败,这个组合本身就是教训:
**该平台的 wave intrinsic 正确性只能在目标内核的就位形态里验证**。

## 5. 附:直方图"多路累加"家族的终审(2026-10-19 问答记录)

问:smem 多份副本/波内 16 车道分组各自累加、最后再归并,能不能救 pass-1 的原子成本?

答:不能,且每一档都有实测或算术:

- **每 warp 一份**(8 份):fp8 探针 E 臂实测与不复制**逐拍相同**(均匀 360.7、
  拥挤 58.3)——成本单位是原子**发射率**,与地址分布无关。
- **波内 16 车道一份**:唯一没测过的形态,它切的是波内同址串行(E 臂没切到)。
  但它只治拥挤;现行 12 位 4096 桶下生产分布与均匀同速(677 vs 678),拥挤
  不是现实。且 smem 16 KB×4 组 = 64 KB → 占员率 4→1 CTA/SM,必亏。
  **真正的用武之地是将来的 fp8 路径**:256 桶 × 4 组 = 4 KB 装得下,且 fp8 的
  拥挤臂(58 GB/s)是真问题——留作 fp8 立项时的第一个待测形态。
- **线程内寄存器预聚合**:探针 F 臂实测 427 vs 678(固定 ALU 成本 > 省的原子)。
- **减桶数换副本空间**:拥挤分布炸(256 桶拥挤 116 GB/s)。

结论:这个内核的原子约束是"条数"不是"争用";能减条数的只有采样(已否决,
见 §3)或不建直方图(一趟式,待立项)。
